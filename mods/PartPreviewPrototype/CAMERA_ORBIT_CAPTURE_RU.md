# Одноразовый захват центра орбиты камеры

Статус: первая реализация в `diagnostic/bone-case-probe`.

## Цель

Камера вращается вокруг сохранённого геометрического центра предпросматриваемой детали. Сам `previewPart` и его render-компоненты не перемещаются и не поворачиваются после создания. Центр вычисляется один раз на время жизни окна и хранится в полях диалога.

## Разделение ответственности

- Центр орбиты берётся из AABB и хранится в координатах `previewRoot`.
- Дистанция камеры остаётся на существующем `GII_SIZE` и текущем zoom. Геометрические bounds не изменяют `modelSize`.
- При ожидании native-центра камера уже имеет предварительную матрицу, построенную вокруг direct-mesh AABB, если он доступен, иначе вокруг начала `previewRoot`.
- После фиксации центра `animate()` больше не запрашивает AABB/native center.

## Захват и проверка готовности

1. Первые два вызова захвата после включения animation hook пропускаются, чтобы render instance успел пройти первоначальную инициализацию.
2. Затем запрашиваются три координаты native transformed-AABB center (оси 500..502), но только если найденный вложенный mesh является допустимым источником: у Part нет direct mesh либо вложенный mesh ID совпадает с direct mesh ID.
3. Первый валидный результат сохраняется как кандидат.
4. На следующем кадре запрашиваются координаты повторно. Центр фиксируется, если все три fixed-point координаты совпадают с кандидатом с допуском в одну единицу (0.001 world unit). При расхождении кандидат заменяется новым результатом и проверка повторяется.
5. Ожидание ограничено 30 animation frames. При таймауте используется уже кэшированный direct-mesh AABB center; если его нет — начало `previewRoot`. Fallback явно записывается в trace.

Если native-путь неприменим, но direct-mesh AABB уже валиден, этот кэшированный центр фиксируется после двух пропущенных кадров без дополнительных native-запросов.

## Текущие границы реализации

Native axes 500..502 вычисляют transformed AABB center одного поддерживаемого embedded type-5 mesh через render instance. Это покрывает проверенные single-mesh nested случаи, включая пружину без direct `getMesh()`, и direct/nested совпадающие ID. Это **не** является обходом произвольного набора отдельных mesh resources в compound Part. Для таких деталей потребуется отдельный этап: полный обход render-resource collection и объединение шести координат преобразованного AABB каждого меша.

Несколько vertex groups внутри одного `RESOURCE_MESH` уже собираются существующим live-AABB helper. Этот факт не означает, что helper объединяет разные `RESOURCE_MESH` ресурсы.

## Защитные ограничения

- Не изменять transform/pivot `previewPart` ради камеры.
- Не вызывать `setMatrix()` для `previewPart` при вращении.
- Не менять native EXE и native dispatcher в этом этапе.
- Не выводить camera distance из AABB радиусов; сохранять `GII_SIZE`.
- Получать центр независимо от наличия курсора.
- Если координаты невалидны или не стабилизировались, не интерпретировать sentinel/нулевые поля как реальный центр.

## Проверка в игре

Нужны отдельные проверки:
- обычная кузовная деталь с direct `getMesh()`;
- пружина без direct `getMesh()`, с embedded type-5 mesh;
- OCA bumper с direct/nested mesh ID match.

Для каждого теста проверить: камера сразу имеет матрицу; центр фиксируется после задержки; после фиксации AABB axes 500..502 больше не опрашиваются; деталь остаётся видимой; вращение камеры не меняет transform и pivot самой детали. Отдельные compound Parts с несколькими самостоятельными mesh resources пока не считать поддержанными.
